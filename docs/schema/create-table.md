# Creating a table

The create form is phpMyAdmin's column definition form adapted to PostgreSQL: one row per column, then the table's comment, owner, tablespace, parents and partitioning, with **Preview SQL** and **Save**. Open it from the **Create new table** card at the bottom of a schema's [Structure](/schema/structure) tab, or go to `/db/<database>/schema/<schema>/create-table`.

<Clip src="schema/tables-create-table.mp4" caption="Creating a table with an identity primary key and a NOT NULL text column" />

## Steps

1. On the schema's **Structure** tab, type a **Table name** and the **Number of columns** in the **Create new table** card, and click **Create**.
2. Fill in one row per column (see [Column attributes](#column-attributes)). Rows whose **Name** is empty are ignored, so spare rows do no harm.
3. Need more rows? Type a number next to **Add … column(s)** at the top and click **Go**.
4. Set the [table options](#table-options) under the grid if you need them.
5. Click **Preview SQL** to see the statements, then **Save**.

On success you get *Table … has been created.* and land on the new table's [Structure](/table/structure) tab. On an error the form stays as it is, with PostgreSQL's message in the corner; see the warning under [Table options](#table-options) about errors after the table was already created.

## Column attributes

| Field | What it does | SQL |
| --- | --- | --- |
| **Name** | Column name, up to 63 characters. Quoted only when needed. | `title` |
| **Type** | The data type (see [Type list](#type-list)). | `character varying` |
| **Length/Values** | Length of a character or bit type; precision of `time`, `timestamp` and `interval`; `precision,scale` for `numeric`. Ignored for other types. | `(200)`, `(8, 2)`, `timestamp(3)` |
| **Default** | **None**, **As defined:** (opens a text box), **NULL**, **CURRENT_TIMESTAMP**, **UUID**. | `DEFAULT …` |
| **Collation** | Any collation of the server, including ICU and your own. Empty means the type's default. | `COLLATE public.case_insensitive` |
| **Attributes** | **ARRAY** makes the column an array of the type. | `integer[]` |
| **Null** | Ticked (the default) allows NULL; unticked adds `NOT NULL`. | `NOT NULL` |
| **Index** | **PRIMARY**, **UNIQUE** or **INDEX** on this column. | see below |
| **A_I** | Makes the column an identity column. | `GENERATED BY DEFAULT AS IDENTITY` |
| **Comments** | Column comment. | `COMMENT ON COLUMN …` |

### Type list

The **Type** select groups the common built-in types the way phpMyAdmin groups MySQL's: **Numeric** (including `smallserial`, `serial`, `bigserial` and `money`), **String**, **Date and time**, **Boolean**, **Binary** (`bytea`), **JSON**, **UUID**, **Network address** and **Geometric**. **Other** lists every other type the database knows: enums, composite and range types, domains (`isbn13`, `email` in the demo), extension types such as `citext`, and the internal `reg*`/`pg_*` types.

Array types are not in the list; pick the element type and set **Attributes** to **ARRAY**. Only one dimension is offered (`integer[]`), which is all PostgreSQL enforces anyway.

### Defaults

| Choice | Generates |
| --- | --- |
| **None** | No `DEFAULT` clause. |
| **As defined:** | The value you type, quoted as a string literal, unless the type is numeric or boolean or the value looks like a function call (`now()`, `nextval('s')`). `it's` becomes `'it''s'`. |
| **NULL** | `DEFAULT NULL`. |
| **CURRENT_TIMESTAMP** | `DEFAULT CURRENT_TIMESTAMP`. |
| **UUID** | `DEFAULT gen_random_uuid()` (built in since PostgreSQL 13). |

::: warning "As defined" quotes keywords and casts
Only a value of the form `name(…)` is passed through as an expression on non-numeric types. `CURRENT_DATE` on a `date` column becomes `DEFAULT 'CURRENT_DATE'`, which PostgreSQL rejects, and `'x'::text` on a `text` column becomes the string `'''x''::text'`. Use a function call where one exists (`now()`, `clock_timestamp()`, `gen_random_uuid()`), or set such defaults afterwards on the SQL tab: `ALTER TABLE t ALTER COLUMN c SET DEFAULT CURRENT_DATE;`. On numeric types the value is used as typed, so `1+1` is accepted as an expression.
:::

### Keys and indexes from the Index column

- **PRIMARY** on one or more rows makes one primary key over those columns, in row order: `PRIMARY KEY (id)` inside `CREATE TABLE`. The columns become `NOT NULL` automatically.
- **UNIQUE** adds a one-column `UNIQUE (col)` constraint per row.
- **INDEX** adds a separate `CREATE INDEX ON t USING btree (col);` per row after the table.

PostgreSQL names them itself (`tbl_pkey`, `tbl_col_key`, `tbl_col_idx`). For multi-column unique keys, other index methods, partial indexes, check, foreign key and exclusion constraints, save the table first and use the [Structure tab](/table/indexes-constraints).

### Identity columns (A_I)

**A_I** stands in for MySQL's `AUTO_INCREMENT` and makes the column `GENERATED BY DEFAULT AS IDENTITY`. It works on `smallint`, `integer` and `bigint`. Untick **Null** too, or PostgreSQL adds `NOT NULL` for you (an identity column cannot be nullable).

::: info Identity or serial?
`serial`/`bigserial` (in the **Numeric** group) create a sequence owned by the column and a `nextval()` default; they are a shorthand, not a type, and the column then shows as `integer` with that default. Identity columns are the SQL-standard form: the sequence is tied to the column, permissions follow the table, and `TRUNCATE … RESTART IDENTITY` resets it. Prefer **A_I** for new tables.

The form always uses `BY DEFAULT`, which lets an `INSERT` supply its own value. `GENERATED ALWAYS` (which refuses explicit values unless `OVERRIDING SYSTEM VALUE`) is not offered; run `ALTER TABLE t ALTER COLUMN id SET GENERATED ALWAYS;` on the SQL tab if you want it. The table's Structure tab shows which kind a column has (**Identity (ALWAYS)** or **Identity (BY DEFAULT)** under **Extra**).
:::

## Table options

Under the grid:

| Field | What it does | SQL |
| --- | --- | --- |
| **Table comments:** | Table comment. | `COMMENT ON TABLE …` |
| **Owner:** | Role that owns the table. Empty means you. | `ALTER TABLE … OWNER TO …` |
| **Tablespace:** | Where the table's files go. Empty means the database default. | `TABLESPACE …` |
| **Inherits from** | One or more parent tables (Ctrl-click for several). Their columns are added to the new table. | `INHERITS (public.books)` |
| **Partition by:** | **RANGE**, **LIST** or **HASH**, and in the parentheses the column list or expression. | `PARTITION BY RANGE (placed_at)` |

::: warning pg_global is listed but cannot hold tables
The **Tablespace** list includes `pg_global`, which is reserved for shared catalogs; choosing it fails with *only shared relations can be placed in pg_global tablespace*.
:::

The partition definition is only the parent's `PARTITION BY` clause; you add the partitions afterwards on the new table's Structure tab. See [Partitions and inheritance](/table/partitions).

![Preview SQL for the form above](/media/schema/tables-create-preview.png)

The preview of the form shown above is:

```sql
CREATE TABLE public.tbl_cap_shelf
(
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    label character varying(80),
    price numeric(8, 2) DEFAULT 0,
    tags text[],
    PRIMARY KEY (id),
    UNIQUE (label)
);

COMMENT ON TABLE public.tbl_cap_shelf
    IS 'Scratch table for the docs';

COMMENT ON COLUMN public.tbl_cap_shelf.label
    IS 'Shown on the shelf';

CREATE INDEX
    ON public.tbl_cap_shelf USING btree
    (tags)
;
```

The Preview SQL box has a fixed height and scrolls when the statement is longer.

::: warning Saving is not one transaction
`CREATE TABLE` runs first and the comments, owner change and separate indexes after it. If a later statement fails, the table already exists: for example an **INDEX** on a `json` column fails with *data type json has no default operator class for access method "btree"*, but the table is created without that index. The form stays open with the error, and a second **Save** fails with *relation … already exists*. Open the table from the tree and fix it there.
:::

## What the form does not offer

These table and column features exist in PostgreSQL but have no field here. Create the table with the form, then add them with `ALTER TABLE` on the schema's [SQL tab](/tools/sql), or write the whole `CREATE TABLE` there.

| Feature | SQL to use |
| --- | --- |
| `UNLOGGED` tables (no WAL, emptied after a crash) | `CREATE UNLOGGED TABLE …` or `ALTER TABLE t SET UNLOGGED;` |
| Generated (computed) columns | `ADD COLUMN c tsvector GENERATED ALWAYS AS (to_tsvector('simple', title)) STORED` |
| Identity `ALWAYS`, identity sequence options | `GENERATED ALWAYS AS IDENTITY (START WITH 1000)` |
| Column `STORAGE` and `COMPRESSION` (`pglz`/`lz4`) | `ALTER TABLE t ALTER COLUMN c SET STORAGE EXTERNAL, ALTER COLUMN c SET COMPRESSION lz4;` |
| Storage parameters (`fillfactor`, autovacuum settings) | `CREATE TABLE … WITH (fillfactor = 70)` or `ALTER TABLE t SET (…)` |
| `LIKE other_table INCLUDING ALL` | Use [Copy table](/table/operations#copying-a-table) on the source table's Operations tab. |
| Check, foreign key and exclusion constraints | The new table's [Structure tab](/table/indexes-constraints). |
| Table access method (`USING heap`) | `CREATE TABLE … USING am` |

Generated columns created with SQL show the expression in the **Default** column and **Generated** under **Extra** on the Structure tab, as `books.search` does in the demo.

## Coming from phpMyAdmin

| phpMyAdmin field | Here |
| --- | --- |
| **Storage Engine** | Not applicable. All tables use PostgreSQL's heap storage. |
| **Collation** (table) | No table-level collation: set it per column. |
| **A_I** | Identity column, `GENERATED BY DEFAULT AS IDENTITY`. |
| **Attributes**: `UNSIGNED`, `on update CURRENT_TIMESTAMP` | Not in PostgreSQL. Use a `CHECK (col >= 0)` constraint, and a [trigger](/table/triggers) for "on update" timestamps. The **Attributes** select offers **ARRAY** instead. |
| `ENUM('a','b')` in **Length/Values** | Create an enum type first ([Types](/schema/types)), then pick it under **Other**. |
| **Virtuality** (generated columns) | Not in the form; see the table above. |
| **Partition by** with partition rows | Only the `PARTITION BY` clause here; partitions are added on the Structure tab. |
| Column **Move** / position | PostgreSQL has no column order clause; new columns always go at the end. |
